# Windows 已为登录之后的往来消息备下“防拆封条”——按微软计划，2027年5月起，服务器将在适用的 NTLM 连接上开始验封

每个工作日里，Windows 电脑都要一遍遍向别的机器证明自己的使用者是谁：文件服务器、打印机、内部网站、各类业务系统，皆在其列。担此差事的诸多机制之中，有一套由来已久，名叫 NTLM，全称 NT LAN Manager。它是一种身份验证协议，所谓协议，就是两台电脑核对身份时共同遵守的一套规矩。微软至今仍支持 NTLM，同时把另一套协议 Kerberos 称作自家在身份验证上的首选。2026年11月10日，微软开始分两步调整 NTLM 对“验明身份之后那些往来消息”的保护。第一步，更新过的 Windows 电脑默认主动提出给消息加上一道密码学意义上的防篡改校验，这道校验叫作“签名”；与此同时，处于标准设置的服务器，对缺少这道校验的来者照样放行。第二步定在2027年5月，届时 Windows 服务器按计划开始要求签名。

“主动提出”与“明文要求”之间这段距离，正是整件事的要害所在。它说明了一项安全更新何以真实有用，而许多连接仍会照旧方式往来数月之久。它也给每一个仍依赖 NTLM 的机构出了一道切实的题目：2027年5月到来之前，怎样查清自家哪些连接已经带上校验，哪些到时会被拒之门外？

## 门口的工牌，包裹上的封条

要看懂这次调整，先得把安全系统所做的三件事分开。三者常常发生在两台电脑的同一番对话里，最容易混为一谈。

头一件是身份验证。它好比查验来人的身份：服务器收集证据，确认连进来的人或程序确实掌握正确的凭据。NTLM 用的是微软所说的“挑战—应答”方式：服务器出一道题，客户端作答，答法只有握有正确秘密的一方才能做到。应用程序也可以借 NTLM 建立微软所称的“安全上下文”，即双方共同约定的一套安排，决定此后说的话如何受保护。

第二件是完整性，NTLM 靠签名来提供。双方验明身份之后，会共享一把“会话密钥”。会话密钥是专属于这一次对话的秘密数值，与用户本人的密码另属两物。开启签名后，每条受保护的消息都附带一个用这把密钥算出的数学校验值；接收方照样再算一遍，两相吻合，便知这条消息与共享会话相符，途中保持原样。

第三件是机密性，在 NTLM 的用语里叫“封装”（sealing）。封装借加密把消息内容搅成一团乱码，旁观者看去只见天书。

可借一个日常比方把三者分开——这只是比方，所述皆为假设。设想一座大写字楼。在门口向保安出示工牌，好比身份验证。到了下午，你往别的楼层寄几个包裹：给每个包裹缠上防拆胶带，一旦被拆便会留下撕痕，这好比签名；把东西装进遮光、上了锁的箱子，好比封装。门口那张有效的工牌，能说明是谁走进了大楼；至于下午三点送到的那个包裹抵达时的模样，工牌所能说明的就很有限了。防拆胶带也照样让人透过透明包装看见里面的东西，遮掩内容是锁箱的另一份差事。比方自有其边界：真实的胶带与真实的密码学都要依赖一定条件，这里把两者都当作坚实而各有局限的防护来看。

签名与几样同名之物也各有分别。它和网站、软件所用的数字证书签名属于两回事；用户的密码在此保持原样；它所覆盖的，是一个协议的一项属性，比“整个网络安全”这种说法要小得多。

## 11月10日起了什么变化

微软于2026年11月10日发布的支持文章说，当天及之后发布的 Windows 更新，开启了 NTLM 消息签名改进的第一阶段。微软把这项工作与一个编号为 CVE-2026-118737 的漏洞挂钩。CVE 意为“通用漏洞披露”，是一份给每个安全缺陷编上识别号的公开目录。2026年11月11日核查本文所据文件时，微软为这一编号单设的漏洞记录页面访问失败，因此该漏洞的严重程度与利用状况，此处仍有待核实。

微软同日发布的另一份文件，是 Windows 11 一次安全更新的发行说明，其中描述了同样的客户端行为，适用于 Windows 11 的 24H2、25H2 和 26H2 三个版本。这份说明的范围止于这三个点名的版本，其他 Windows 版本的情形，当以各自产品的发行说明为准。两份文件同出微软之手，彼此一致，印证的是微软对自家所发布内容的说法；独立的外部测试，则在这些文件范围之外。

第一阶段里，更新后的 Windows 客户端，会在相关的、关联具体账户的 NTLM 连接上默认提出密码学签名。所谓关联具体账户，是相对于开放访问或来宾访问而言的。按照文档所述的默认设置，Windows 服务器对带签名与缺签名的客户端一并接纳。由此可见，第一阶段改的是每一次协商时的“开价”，服务器的门依旧向回绝签名的一方敞开。

这里还有两层区分。微软发布更新，意味着更新可供取用；装到某台具体电脑上，是各机构自行掌握的另一步。装上之后，某一条连接最终的签名状态，仍取决于双方协商的结果。微软的文件讲清了机制；真实世界里的普及程度与实际成效，须从各机构自己的记录中去测量。

## 名字令人安心，实情却弱一些

微软文章里最耐人寻味的细节之一，关乎一个名字颇有底气的设置。NTLM 里有个老标记，叫 ALWAYS_SIGN，听来仿佛每条消息都会签名。微软文档解释说，这个遗留标记单独存在时，只起占位作用，消息仍欠缺密码学上的完整性保护。据微软所述，那些请求了某些完整性相关属性的应用，得到的是真正的签名；而另一些省略了这些请求的应用，可能落入一个挂着安心名号、却少了那道真校验的上下文。

放回写字楼的比方里，这就像一个包裹盖着“防拆”二字的戳，缠的却是普通胶带。戳印看着可靠，胶带照旧是寻常胶带。

这一细节须小心对待。NTLM 支持真正的密码学签名由来已久，微软也说明，所有仍在支持期内的 Windows Server 版本都已具备这一能力。11月的调整，关乎客户端默认索要什么，以及日后服务器要求什么。ALWAYS_SIGN 一事给人的启示更窄也更实在：要紧的是一条连接实际协商出的保护；一个标签、一次成功登录、一个听来安心的设置名，各自只说出了故事的一部分。

## 防篡改校验为何要紧：中继

微软声明的目标，是减少“中继攻击”带来的暴露。概而言之，中继是这样一回事：有个中间人插身于用户电脑与另一台机器之间；用户电脑发起一次正当的身份验证交换；中间人把这番交换转送到另一个目的地，在那里借用户的身份行事。中继靠的是转发，所以中间人可以在用户密码始终对其保密的情况下尝试此举。窃取密码与中继登录，是两道各异的难题。

签名收窄了中继者在登录成功之后所能做的事。受保护的后续消息，需要真正双方共享的那份会话安全；缺少会话密钥的中间人，难以造出能通过接收方校验的消息。回到比方里：有人尾随真员工混进了大楼，可一旦每个包裹都须缠上只有真寄件人才能缠的胶带，他依旧要碰壁。

这份好处的范围，也须说得同样清楚。微软所描述的，是针对它所指认的那一类中继行为，暴露有所减少；文件把这份好处呈现为设计上的预期效果。离线猜解密码、恶意软件、针对人的骗术，以及网络遭受攻击的其他诸般途径，各是另一类威胁，各有另一套防御。

## 有意留着的几扇门

微软在第一阶段刻意保留了兼容空间，文档描述了三种开口。

其一是回退。若客户端提出签名，而服务器的回应里缺少相应的签名支持，微软记载了一条路径：客户端撤回签名请求，沿用旧的行为继续往下走。连接照常运作，带着的是较旧、较弱的保护。这条路径与眼下阶段相宜，因为服务器两类来者都接纳。对于执行第二阶段要求的服务器，微软文件描述的是另一种结局：在适用的连接上，省略签名的客户端将被拒绝。所以，回退为过渡期铺平了道路，到了过渡期之后，它能给的保证就单薄得多了。

其二留给匿名连接（又称空会话）和来宾会话。微软文档把这两者排除在签名要求之外，第二阶段亦然。理由出于技术，协议规范里写得明白：这类会话缺少签名所依赖的会话密钥。签名需要一份共享秘密，而这类会话手中恰恰欠缺。这一例外的范围限于签名，说的是协议如何对待此类会话。某个具体来宾账户能触及哪些资源，取决于各产品、各机构如何配置，那是另一个问题，微软的签名文档把它留给了这些设置去回答。

其三关乎微软的承诺覆盖哪些机器。微软说的是，仍在支持期内的 Windows Server 版本都能签名。已过支持期的旧版 Windows 系统，以及其他厂商生产、同样使用 NTLM 的设备，比如存储设备或专用设备，都在这句话的范围之外，它们如何表现，要看各自厂商与设置。

## 倒数至2027年5月

第二阶段会改变局面的分量。微软计划在2027年5月让 Windows 服务器默认要求 NTLM 签名；文件给出了月份，具体日期留白。按照这一计划，在适用的连接上回绝签名的客户端，会被执行该要求的服务器拒绝。微软还说，管理员在评估兼容性之后，可以选择提前开启强制要求。截至11月11日核查之时，第二阶段是一份已公布的计划，服务器在默认状态下依旧接纳缺签名的客户端，而计划也可能调整。

拒绝，正是强制执行的意义所在。一道可以随意回绝的防篡改校验，只护得住那些愿意使用它的一方。执行这一要求的服务器，会在所适用的连接上索要签名，匿名会话与来宾会话依旧在例外之列。它所索要的校验，仍要依赖会话密钥与协议本身的条件；所以，这项要求抬高的是受覆盖连接的底线，离“万全的安全保证”还差着一截。同一种拒绝，也可能拦下一个老旧应用、一台年久的设备，或者一项难得运行一次、恰好依赖缺签名路径的业务流程。第一阶段让这些依赖悄然照常运转；到了第二阶段，凡是仍在的，都会浮出水面，或许以故障的面目出现。

于是各机构需要证据，微软指向的来源是审计日志。在 NTLM 运行日志里——这是 Windows 为自身活动所记的诸多账簿之一——客户端电脑可以记录 4022 号事件，服务器可以记录 4023 号事件。微软记载，在 Windows Server 2019 及更高版本上，配合相应的增强审计，可以得到这些事件的增强版本。管理员可据这些记录，去寻找协商了签名的连接与略过签名的连接。

读这些记录须用心。微软文章指出，带签名与缺签名的连接都可能以同样的“警告”级别出现；单凭严重级别这一标签，所得的答案残缺。事件内部关于协商结果的那些细节，才是关键所在。

更难的是覆盖面。一次审计，是在某段时间里对现实所取的一个样本。季度一次的工资核算、一年一次的归档传输、大多数星期闲置一旁的某台设备，都可能在短暂的观察期里于日志中悄然静默，等到它的日子来了，却依旧依赖缺签名的 NTLM。几天之内搜索结果为空，说的只是那几天的情形。一幅可信的就绪图景，需要明确的观察时段、来自相关客户端与服务器的记录，以及对哪些应用走哪条路径的了解。这份了解往往掌握在各个应用的负责人手里，他们与管理 Windows 更新的人、与日常使用系统的普通员工，各是一群人。

两类证据也宜分开看待。网络上出现缺签名的 NTLM 流量，属于兼容性证据，它标出了一条在强制执行到来之前或许需要留意的连接。遭人入侵的证据另属一类；单凭缺签名流量本身，归在兼容性那一类。

## 更大的图景，与留待作答的问题

这次调整，身处一场更长的过渡之中。微软的技术背景资料把 Kerberos 列为其首选的身份验证协议，而 NTLM 之所以仍在使用，很大程度上是因为老旧应用与设备依旧依赖它。11月的变化只作用于 NTLM，Kerberos 在其范围之外。NTLM 照常运转，Windows 身份验证的其余部分也保持原位。此番所关者是签名，也就是完整性校验；封装，即 NTLM 另行提供的机密性保护，回答的是另一道问题，而各应用的加密安排本就各有其式。这次变化所做的，是分阶段收紧一个广泛使用的协议的一项属性：先以更稳妥的默认开价和更清楚的可见性起步，再一步步走向更坚定的要求。

微软的文件确立了机制、时间表与查看的工具。普及程度、兼容状况与安全成效的测量，若有其事，将存在于各机构自己的记录里，由熟悉哪些系统要紧的人，循其所动，日积月累地汇集起来。

于是，第一阶段悄然引出一个问题。从现在到2027年5月某个仍待公布的日子，每个依赖 NTLM 的机构都有一段时日，可以在校验已经提出、大门依旧敞开之际，观察自家的往来流量。它的日志，会揭示出多少一直缠着普通胶带往来的连接？那些最罕见的几条，又能赶在服务器开始验封之前被找到吗？
