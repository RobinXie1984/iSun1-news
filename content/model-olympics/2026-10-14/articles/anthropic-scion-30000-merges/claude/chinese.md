标题三则

一、悬念： 《日并三万，旧器难承：Anthropic 何以弃 Git 而另起炉灶？》

二、情感共鸣： 《七人五月，铸器承潮：机巧日盛，人心犹执其舵》

三、反直觉： 《智械非解困之钥，乃移困之手：码成愈速，关隘愈窄》

日并三万，旧器难承：Anthropic 何以弃 Git 而另起炉灶？

凡例：本文所据，乃 Anthropic 于二〇二六年十月十三日所刊工程报告。文中诸数，皆其自述之内部数据，非第三方独立测得。凡事实者，直书其事；凡己见者，冠以"愚谓"，以示区别。

序：一数惊人

试观二数。

二〇二六年五月，据 Anthropic 所述，日并代码变更约二千五百。

同年九月，日并逾三万。

前后不过四月。以算术计之，增逾十二倍。

世人言智械与代码，多谓其要在于"疾书"：一人之力，倍于往昔；功能速成，积压立清。然此报告所述，乃疾书功成之后事也。

据其源码管控团队言，此等增长，令基础设施反成瓶颈。困不在写，而在纳、在记、在验。

速者不灭其困，徙其困于下游耳。

一、管道之困，遂为大事

Git 者，治代码之器也，行世近二十载。分布而稳，通行天下，习焉不察，几若无形。

然无形之器，自有其弊：平时不觉，力竭方知。

Anthropic 自述其事如下：

自五月至九月，日并变更由约二千五百，增至逾三万。
源码管控团队谓，此增长使基础设施成为制约。
其所造模型 Claude，助成此量。

此一转折，耐人寻味。其所以撞墙，非因新品一夜风靡，亦非广募人手；据其自述，压力多半源于智械日夜不息，提交变更，其势之疾，旧器未尝预料。

愚谓： 往昔代码之事，最贵者乃工程师之光阴。智械既出，光阴稍丰，则稀缺之物，转移至"码已写成"与"码被纳入"之间：审阅、测试、合并、存储、算力是也。此报告者，一司之中，此变方萌之实证也。

二、七人五月，另铸新器

Anthropic 不事修补，另起炉灶。

据报告所载：

七人小队，自建源码管控系统，名曰 Scion；
并造审阅工具，名曰 Antique，及相关诸系统；
历时五月，将全司单体代码库（monorepo）尽数迁离 Git；
Claude 参与构建此新器；
架构之定，变更意图之审，仍由人类工程师执掌。

末一条，最易一目而过，然最宜细读。

此非智械自造其器、无人监之之事。据 Anthropic 所述，分工井然：机司其筑，人定其向。何者当建，人决之；每一变更是否如其所言，人审之。

机能书其变，然变之所以当有，必待人知之。

此中有一循环，不可不察：Claude 助生洪流，旧器因之不支；Claude 又助造新器，以承此洪流。解铃还须系铃人，而执缰者，始终是人。

愚谓： 七人五月，迁一司之库，殊为可观。然报告未详其速之由：几分出于智械之助，几分出于团队之能，几分出于范围之取舍，皆未明言。故不宜妄归一因。可确言者，唯 Anthropic 择自建而舍购改，且自述迁移已竣耳。

三、新器之异，在于何处

Anthropic 述 Scion 之设计，略有数端：

在线客户端：开发者连于实时系统，不各自怀抱全库；
服务端运算：重务移于中枢，不累个人之机；
稀疏、按需之数据：用时方取，取其所需。

熟谙 Git 者，当知此与其立身之本背道而驰。Git 之设，令人人尽携全史，离线亦可为之；于散处四方之开源社群，此诚其长。然一司一巨库，变更如潮，川流不息，则此长反为其累。

愚谓： Scion 非"更佳之 Git"，乃另择其道也。Git 分其担于众，Scion（据所述）聚其担于中。孰优孰劣，因地制宜，视其负载而定。此正 Anthropic 自陈之戒，详见下文。

四、"二百倍"之数，所言几何

此处最易以讹传讹，宜缓缓而论。

Anthropic 报二果：

较之此前 Git 镜像设施，CPU 与内存之基础设施占用，缩小二百倍；
持续集成（CI，即代码自动构建与测试）之 CPU 容量，获益百分之二十五。

此二者，各为一量，所测不同。

"二百倍"者，非谓：

总成本省二百倍；
万事皆速二百倍；
他人用之，亦得此效。

其所比者，唯 Scion 之 CPU 与内存占用，较 Anthropic 旧日 Git 镜像设施而已，仅此一端。

至于 CI 之百分之二十五，其数虽平，实为清醒之鉴。CI 者，凡变更必经之关；日并数万，则其算力耗费不可小觑，收回四分之一，诚非细事。然二十五者终非二百，二数不可混为一谈，合成一则惊人之语。

数之最巨者，未必最要；须问其所比者何物。

愚谓： 二数皆可视为方向之可信征兆，然出自造器者之口，述其自家之境。外人未于相类负载复现之前，此乃其言，非定论也。

五、白纸黑字，自陈其限

报告之中，愚最愿世人细读者，正在此节。盖 Anthropic 几乎亲手驳去此事最夸张之版本。

据其所言：

Scion 不宜作通用之 Git 替代；
其负载异乎寻常之巨；
其内部 token 耗费亦异乎寻常之巨；
尚无公开、可直接替换之发布版本。

故若五人小司，欲明日尽弃 Git：据 Anthropic 自述，此器本非为君而设，亦无现成之器可供改弦易辙。

更有数事，日并之数不能证之：

变更多，不证代码质量更佳；
变更多，不证盈利更丰；
变更多，不证工程师遭裁撤。

末一条，尤须重申，盖此最易望文生义。报告之中，无一语言 Anthropic 因此裁人。所知人事之细节，唯七人建器，及人类仍执架构、审意图而已。

量者，动之度也，非值之度也。 日并三万，足以言其吞吐之盛；然仅凭此数，不足以言其变更之善。

六、尚未可知者

信史之道，知之为知之，不知为不知。据现有材料，悬而未决者有三：

独立复现：其性能之数，尚无第三方验之；
全盘经济：建造、运行、维护 Scion 之总费，及与旧制全面相较之账，皆未得见，所见者唯 CPU 与内存一端；
他处适用：Anthropic 自谓其境特殊，此法能否移于他司，未可知也。

诸阙虽在，无损其趣。然此当以案例观之，不当以定谳观之。

七、真义所在，不在 Git

以下纯属愚见。

世间易传之说，曰"智械诛 Git"。此非实情，Anthropic 亦自言其非。Git 未死；一司负载极端，自内易之而已。

更可久者，乃一理焉：智械促速之时，压力流向何方？

譬如一坊，忽得一机，制件之速，十倍于前。然验、装、运三道不随之而疾，则件不能十倍而出。须臾之间，众人所瞩，不在新机，而在码头矣。

代码亦有其码头：版本管控、代码审阅、自动测试、部署上线。数十年来，诸器皆按人之步调而设，盖人乃最缓之一环。此报告示之：此一前提，至少于最高处，可以崩也。

为用智械者计，愚有四言：

其一，量其渠，勿只量其源。
智械增产之后，当问下游何如：审阅之队是否日长？CI 算力是否日攀？合并之时是否日延？下一瓶颈，多不在君所注目之处。

其二，人之判断，升而不没。
Anthropic 所述，人掌架构，审其"变更意图"。此语意味深长。机既能生其变，人之职遂聚于一点：此变当否存在？是否名实相副？此事难以机代，其值或反更高。

其三，读司之自测，当如读司之盈利指引。
有用、有据，然出自利害相关者之手。Anthropic 附以严谨之限语，殊为可嘉；正因如此，凡引其数者，当使限语与数同行。

其四，勿袭其方，当袭其诊。
自建源码系统者，世间寥寥。然 Anthropic 所问之事，众人终将自问：吾之流程，何处乃为迟缓之世所筑，而人未之觉？

结语：一言以蔽之

智械之初任，在使事速；其次任，今方至，在重建一切未为此速而设之物。

Anthropic 此报，乃一司先于众人、步入次阶之自述。其数自报，其器明言非通用，其费与其可移，尚多悬疑。然其所述之困局，形制已具，他日当以或大或小之貌，见于各处。

所当问者，非君之团队他日是否须弃 Git。

乃君之 Git，究为何物？

敢问诸君： 若明日智械令君之团队产出倍增，何处先崩？审阅耶？测试耶？审批耶？部署耶？抑或从无人察之某隅？愿闻高见，请留言相告。 愚意诸君所答，当较任何基准测试，更为纷繁，亦更足发人深省。
